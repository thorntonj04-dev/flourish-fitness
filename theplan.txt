GOAL
----
Transform the app into a focused, mobile-first workout programming and delivery
platform. Remove all food, nutrition, and measurement tracking. The entire
experience — for both admin/trainer and clients — revolves around building
workout programs, assigning them, and performing workouts on an iPhone saved to
the home screen as a PWA.

SECTION 2: DATA MODEL (Firebase Realtime Database)
================================================================================

Current paths that stay:
  /workouts/{workoutId}         Individual workout day templates
  /workout-logs/{logId}         Completed session logs
  /users/{userId}               User accounts + roles

New paths to add:

  /programs/{programId}
    ├── name: string
    ├── description: string
    ├── createdAt: ISO string
    ├── createdBy: adminUid
    ├── archived: boolean
    └── phases/
          ├── 0/
          │   ├── name: string           ("Phase 1 - Foundation")
          │   ├── durationWeeks: number  (4)
          │   ├── workoutsPerWeek: number (3 | 4 | 5)
          │   └── days/
          │         ├── 0/ { id, label: "Day A", workoutId, workoutName }
          │         ├── 1/ { id, label: "Day B", workoutId, workoutName }
          │         └── 2/ { id, label: "Day C", workoutId, workoutName }
          └── 1/
              ├── name: string           ("Phase 2 - Progression")
              ├── durationWeeks: number  (4)
              ├── workoutsPerWeek: number (4)
              └── days/
                    ├── 0/ { id, label: "Day A", workoutId, workoutName }
                    ├── 1/ { id, label: "Day B", workoutId, workoutName }
                    ├── 2/ { id, label: "Day C", workoutId, workoutName }
                    └── 3/ { id, label: "Day D", workoutId, workoutName }

  /programAssignments/{userId}
    ├── programId: string
    ├── programName: string
    ├── assignedAt: ISO string
    ├── assignedBy: adminUid
    ├── startDate: YYYY-MM-DD
    ├── currentPhase: number    (0-based index)
    ├── currentWeek: number     (1-based, within current phase)
    └── weeklySchedule/
          ├── Monday: "day-id-or-null"
          ├── Tuesday: "day-id-or-null"
          ├── Wednesday: "day-id-or-null"
          ├── Thursday: "day-id-or-null"
          ├── Friday: "day-id-or-null"
          ├── Saturday: "day-id-or-null"
          └── Sunday: "day-id-or-null"

NOTE: The weeklySchedule maps days of the week to phase day IDs (e.g., "Day A",
"Day B"). The client can rearrange which day of the week each workout falls on.
Rest days are null. The admin sets a default schedule at assignment time;
the client can override it at any time.

SECTION 5: MOBILE / PWA UX RULES (apply throughout)
================================================================================

These are design rules to follow when building every new component:

1.  TOUCH TARGETS: All buttons/tappable elements min 48px tall. No tiny icons
    as the only interactive surface.

2.  BOTTOM NAV: Already exists, keep it. It's the primary nav on mobile. The
    sidebar (desktop) can stay but mobile users never see it.

3.  THUMB ZONE: Put primary actions (Start Workout, Confirm, Save) at the
    bottom of the screen, not top. Think of where thumbs naturally reach.

4.  NO HOVER-ONLY: No tooltips, dropdowns, or state that only triggers on
    hover. Everything must be tap-accessible.

5.  LARGE TEXT INPUTS: number inputs for sets/reps/weight should be large
    (text-xl or bigger) with big + / - stepper buttons so users don't need to
    type during a workout.

6.  FULL-SCREEN WORKOUT MODE: When a workout is active, it's full screen with
    no nav clutter. This already exists, preserve it.

7.  LOADING STATES: Show skeleton cards (pulsing gray boxes) instead of
    spinners for list loads. Spinners only for action confirmations.

8.  PREVENT ACCIDENTAL EXITS: When in an active workout, "back" or nav taps
    should trigger a "Leave workout? Progress may be lost" confirmation.

9.  PWA: The index.html must include all apple-mobile-web-app meta tags so it
    looks native when saved to the iPhone home screen (no browser chrome,
    proper icon, proper status bar).

10. DARK MODE: Already implemented, keep it. Default to system preference.

SECTION 7: WHAT SUCCESS LOOKS LIKE
================================================================================

ADMIN (on iPhone, saved to home screen):
  - Logs in → sees overview with clients + their program status
  - Navigates to Programs → sees list of all programs
  - Creates a new program: adds phases, sets duration, picks workout days
  - Goes to Clients → assigns the new program to a client with a start date
  - Sets the client's weekly schedule (e.g., Mon/Wed/Fri for a 3x/week plan)
  - Can come back and reassign or switch program for any client at any time

CLIENT (on iPhone, saved to home screen):
  - Logs in → immediately sees "This Week" with Mon-Sun schedule
  - Sees which days have workouts and which are rest days
  - Taps START on today's workout → enters full-screen workout mode
  - During the workout, can tap + / - to adjust weight or reps for any set
  - Finishes → sees summary, any PRs, returns to week view
  - Can tap "Adjust Schedule" to move Wednesday's workout to Thursday
